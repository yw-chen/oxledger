已定決策

D1 · public repo放在使用者個人帳號
D2 · 沿用 GPL v2架構取之於社群；可直接參考 Redmine 原始碼
D3 · GPL-2.0-or-later與 Redmine 檔頭一致，可用 rmcp
D4 · 全新 API、不遷移沒有現有 Redmine 服務；不做匯入器、Textile、舊 API 相容
D5 · 單一組織不做多租戶；要多個組織就各自部署
D6 · SvelteKit SPA渲染 layout JSON；TS 型別由 Rust 產生
D7 · 只支援 PostgreSQL不做 SQLite 單機版
D8 · PostgreSQL 18+主鍵用內建 uuidv7()
D9 · 專案前綴編號AUTH-123；換專案發新號、舊號轉址
D10 · 每請求算可見範圍不物化快取，有瓶頸再重議
D11 · outbox 用 xid8 快照SQL 輪詢，at-least-once + 冪等
D12 · 遮蔽後留痕內容換成 [已遮蔽]，記錄誰、何時、為什麼
D13 · 名稱 oxledgerREADME 寫 derived from Redmine；scheme oxledger://
D14 · 自訂欄位用型別化 EAV每欄位 covering partial index，不加 JSONB 快取（E9：冷門篩選 1–5 ms vs 100–300 ms）02 報告
D15 · 中文檢索維持 unigram+bigram查詢加 0.1–0.2 權重單字（nDCG 0.781→0.810）；別名展開待 E2 03 報告
D16 · AI 原生前端目標是意圖驅動的任務工作台，先做工作台 + AI 側欄；第一版由外部 agent 經 MCP 提 ChangeSet，人審閱套用 設計 01
D17 · 中國來源判定看開發者或公司所在地；直接依賴、模型、詞典、字型、託管服務；間接依賴只列清單
D18 · 自訂欄位支援內建角色篩選和顯示用同一套「實際角色」規則（migration 0003）
D19 · 第一切片決定agent 可多專案委派（受眾包含檢查防外洩）；接受 Redmine 差異；分流逐張提案批次核准；基本排名契約；不就地改型別 待決總表
D20 · agent 直接寫入預設直接寫、可逐項改要核准或不允許；agent 當獨立使用者顯示；配額、熔斷、活動頁與 undo 為防線 02 §16
D3 的背景：rmcp 是 Apache-2.0 單一授權，FSF 認定它與 GPL-2.0-only 不相容、與 GPLv3 相容。Redmine 檔頭本來就是「v2 or any later」→ 建議用 GPL-2.0-or-later。ParadeDB 因 AGPL 網路義務會轉嫁給部署方而不採用。（非法律意見）

架構總覽

資料庫：比 Redmine 好在哪（已依獨立審查修正）

Redmine問題新設計
自訂欄位 EAV（值都是字串）要轉型型別化 EAV issue_cf(field_id, v_num, v_date, v_text…) + partial index；每欄位 covering partial index；不加 JSONB 快取（D14）
nested set搬移改寫同一棵樹parent_id；彙總值寫入時算好存父節點
journals（字串）歷史值查詢要掃字串issue_events + 型別化 issue_field_changes 投影；要有 redaction
private notes—搜尋裡獨立子文件、自己的可見性過濾
polymorphic association沒有 FKexclusive arc（多個可為空 FK + num_nonnulls=1）；entities 只給 edges
可見性每角色 (mode × tracker 集合)、多角色 OR、含群組每個請求先算可見範圍，編成 SQL 與 tantivy filter；先不物化（Q10）
——RLS 只做 project 粗邊界
roles.permissions YAML不能用 SQL 查role_permissions 正規化
settings／queries YAML不可查、不可驗證JSONB + JSON Schema；queries → view_defs
附件存檔名重複sha256，以專案為範圍去重 + GC
審查抓到的四個硬傷（已修）
① 可見性不能用單一欄位快取 ② private notes 會從搜尋洩漏 ③ Postgres sequence ≠ commit 順序，outbox 會漏事件 → 用 xid8 快照或 logical replication（Q11）④ JSONB 撐不住上千欄位的範圍篩選與排序（GIN 不支援範圍、planner 沒統計、寫入放大）

另外：狀態 category todo/doing/done；lock_version + patch 寫入；封存不硬刪；時間點 timestamptz、日期用 date；PG18 才有 uuidv7()（Q13）；tantivy top-k 回 DB 複驗。

AI 查詢流程（ontology × BM25）

1 解析
MCP 參數已結構化；只有 q 自由文字往下走
2 別名展開
concept_labels：登入 → Authentication（login、SSO、sign-in）
3 過濾
參數 + 可見範圍（每角色 mode×tracker、含群組）編成 filter；top-k 回 DB 複驗
4 BM25F
title 3・concept 2・desc 1・commit 0.7・journal 0.5
5 圖擴展
沿 duplicates／parent／blocks 1 跳，L′+γ·G′ 重排
6 精簡回傳
brief 一行約 30 token、facets、cursor

例：「上個 sprint 和登入相關、還沒修好的 bug、誰在處理」→ 一次呼叫：

search(q="登入", tracker="bug", version="@previous_sprint", status_class="open",
       fields=["id","subject","status","assignee","blocked_by"], facets=["assignee"])
→ 10 行 brief + facets.assignee = {Alice:4, Bob:2, 未指派:1}
