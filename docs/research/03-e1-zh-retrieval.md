# 03 — 實驗 E1：繁體中文 issue 檢索品質

> 2026-11-06。對應 `01-redmine-rust-rewrite.md` §5.4 的 E1。程式與資料在 `experiments/e1/`，重跑方式見該目錄的 README。完整結果表在 `experiments/e1/results/summary.md`，逐查詢結果在 `results/per_query.jsonl`。

## 結論

1. **M1 保留 M0 的索引方式（unigram + bigram），不換成詞典斷詞。** 在這份資料上，現行方案 a 的 nDCG＠10 是 0.781，是所有不加別名的基本方案裡最高的。ICU4X（d）0.732、lindera + CC-CEDICT（e）0.746，兩者都沒有贏過 a；d 對 a 的差距在 95% 信賴區間內顯著為負。詞典斷詞還會讓單字查詢失效（「票」「印」找不到東西），而且斷法會隨上下文變（「工時報表」被 ICU 斷成「工／時報／表」）。
2. **建議改 `search.rs` 的查詢端：除了 bigram，把查詢裡的 CJK 單字也加進去，權重 0.1–0.2。** 這個變體（a+uni0.1）nDCG＠10 0.781 → 0.810，recall＠20 0.733 → 0.791，60 題中 12 題變好、3 題變差，平均差 +0.029（95% CI [+0.007, +0.055]）。它修好的是「bigram 在語料裡完全沒出現」的查詢，例如「付不了錢」從 0 筆命中變成 nDCG 0.54。權重拉到 0.5 就會把好處吃掉（+0.006，不顯著），因為單字開始主導排序，「登入／載入」這類誤命中又回來了。
3. **別名展開是最大的單項提升，值得在 M1 先上一個小版本，但要在 E2 用獨立查詢集驗證。** a+alias1 的 nDCG＠10 是 0.857（+0.076，CI [+0.032, +0.127]），同義詞類從 0.500 升到 0.756。再加上第 2 點的低權重單字，a+uni0.2+alias1 是 0.861，整體最高。不過別名表是我看過語料後寫的，這個數字是**上限**，不是可以期待的實際值（見〈限制〉）。
4. **同義詞／換句話說仍是最弱的一類。** 不加別名時各方案只有 0.50–0.59。這一類正是 E8（向量 RRF）要解的問題；建議 E8 照原計畫排在別名展開之後，並以同義詞類的分數作為主要判準。

## 1. 資料集

**全部是合成資料**，由執行本實驗的 Claude（Opus 5.5）依指示撰寫，沒有使用任何外部資料集，也沒有中國來源的語料。

| 檔案 | 內容 |
|---|---|
| `data/issues.jsonl` | 200 筆 issue，台灣用語，模擬軟體團隊的追蹤系統 |
| `data/queries.jsonl` | 60 個查詢，每題標出相關 issue（2 高度相關、1 部分相關、未列為 0），共 378 筆判定 |
| `data/aliases.jsonl` | 20 條別名展開規則 |

**Issue 組成**：登入／SSO／2FA 30、權限 20、付款／發票 25、通知／Email／推播 20、效能／載入 20、當機／閃退 15、部署／CI 20、UI 25、搜尋／報表／匯出 15、其他（備份、同步、Wiki、workflow）10。標題中位數 12 字；標題加描述中位數 43 字、平均 65 字、最長 366 字；21 筆有超過 100 字的長描述（重現步驟、log、堆疊、SQL）。140 筆夾英文術語或錯誤訊息（`invalid_grant`、`EXC_BAD_ACCESS`、`OOM killed`），12 筆帶版本號。

**刻意放進去的難點**：

- 同一件事多種說法：無法登入／登不進去／登入失敗；當機／閃退／掛掉／當掉／crash／沒有回應；很慢／遲緩／延遲／逾時。
- 共用字的誤命中：登入／載入／匯入／輸入（都有「入」）、載入／載具、信（email）／信用卡／信譽、卡住／信用卡／看板卡片、帳號／結帳／帳單、資料／資料庫。

**查詢分類**（每題的 `intent` 欄位寫明使用者想找什麼）：

| 類型 | 題數 | 例子 |
|---|---|---|
| exact 精確詞 | 14 | 登入、權限、發票、甘特圖、webhook |
| synonym 同義／換句話說 | 16 | 無法登入、登不進去、當機、閃退、系統很慢、付不了錢、網頁打不開 |
| mixed 中英混合 | 12 | SSO 失敗、2FA 驗證碼、OAuth 錯誤、k8s 部署、CSV 匯出亂碼 |
| single 單字 | 6 | 信（email）、慢、印、票、鎖、卡（卡住） |
| decoy 易誤命中 | 12 | 載入、匯入、載具、信用卡、卡片、輸入法、時區、帳號鎖定 |

每題平均 6.3 筆相關（最少 1、最多 25），其中高度相關平均 4.2 筆。

## 2. 方案

全部方案用同一個 tantivy schema、同一種查詢形狀（與 M0 `SearchIndex::search` 相同：每個查詢詞一個 Should 子句，標題 boost 3、描述 boost 1，BM25 預設參數），只換斷詞器。英數字一律是小寫的英數字串。

| 代號 | 索引端 | 查詢端 |
|---|---|---|
| **a**（M0 現行） | CJK 單字 + 相鄰 bigram | 兩字以上的 CJK 只用 bigram；單一 CJK 字用單字 |
| a2（對照） | 同 a | 單字 + bigram 全用（不過濾） |
| b | 只有 CJK 單字 | 只有 CJK 單字 |
| c | 只有 bigram（孤立的單一 CJK 字保留為單字） | 同索引端 |
| d | ICU4X `icu_segmenter` 2.4.0 `WordSegmenter::new_auto` | 同索引端 |
| e | lindera 6.2.0 + CC-CEDICT（`embed-cc-cedict`） | 同索引端 |
| a+uni*w* | 同 a | a 的查詢詞（權重 1）+ 查詢中的 CJK 單字（權重 *w*） |
| *x*+alias*w* | 同方案 *x* | 查詢包含別名表的 `term` 時，加入展開詞（權重 *w*） |

a、a2、b、c 直接呼叫 `oxledger::search::tokenize` 與 `tokenize_query`，不是重寫的版本。

### 2.1 方案 d：ICU4X 的詞典來源與授權

- `icu_segmenter` 2.4.0（2026-10-22 發布），授權 **Unicode-3.0**。這是寬鬆授權，可以和 GPL-2.0-or-later 一起散布。預設 feature `compiled_data` 會帶入 `icu_segmenter_data` 2.4.0（同為 Unicode-3.0，壓縮後 3.1 MB，含全部斷詞資料）。
- 文件寫明 `new_auto` 對中文、日文用詞典模型（中日文目前沒有 LSTM 模型）。ICU4X 的資料產生程式（`provider/source/src/segmenter/dictionary.rs`）從 ICU export 讀取 `segmenter/dictionary/cjdict.txt`，也就是 ICU4C 的 **cjdict**。
- cjdict.txt 檔頭說明，詞表由兩份詞表合併後再做複合詞處理，詞頻是用 Google 網頁語料反覆訓練得出：
  - **中文：libtabe**（TaBE 專案、蕭百祥 Pai-Hsiang Hsiao，著作權聲明含中央研究院資訊科學研究所與蔡志浩 Chih-Hao Tsai），BSD 式授權，附不得以專案名義背書的條款。來源是台灣，不是中國。
  - **日文：IPADIC**（奈良先端科學技術大學院大學，大部分詞條源自 ICOT Free Software），允許使用與散布，須保留著作權聲明。
  - 檔頭另註明：原本含有 CC-CEDICT 的詞，因 CC-SA 與 ICU 授權不相容，**CC-CEDICT 獨有的詞已全部移除**。
- 小出入：ICU 的 LICENSE 檔寫「三份詞表」但只列兩份，cjdict.txt 檔頭寫「兩份」。另外沒查到 ICU4X 打包後中文詞典單獨的大小。
- 判斷：來源不是中國，授權相容。經使用者同意後下載，只用在 `experiments/e1`（cargo feature `icu`）。

### 2.2 方案 e：lindera + CC-CEDICT 的來源與授權

- `lindera` 6.2.0（2026-09-26），程式碼 **MIT**。只開 `embed-cc-cedict` feature；`cargo tree` 確認依賴圖裡沒有 `lindera-jieba`（jieba 只會由 `embed-jieba` 或 `embed-cjk*` 帶入）。
- `lindera-cc-cedict` 6.2.0 的 build script 會在編譯時從 **lindera.dev** 下載 `CC-CEDICT-MeCab-0.1.0-20200409.tar.gz`（詞典資料是 2020 年 4 月的版本；GitHub main 分支已改用 20261021 版，但 crates.io 上的 6.2.0 還是 2020 版）。
- CC-CEDICT-MeCab 由 GitHub 使用者 ueda-keisuke 從 CC-CEDICT 轉換，**繁體與簡體都收錄**（詞條以繁體為表層形式）。授權 **CC BY-SA 4.0**。
- CC-CEDICT 是 Paul Denisowski 1997 年開始的 CEDICT 的延續，由 MDBG 網站收集社群修訂，授權 CC BY-SA 4.0。我在詢問使用者時說 MDBG 在德國，**這點沒有查證**，MDBG 官網沒有寫明營運地。
- 判斷：來源不是中國；**但 CC BY-SA 4.0 和 GPL-2.0 不相容**（只能單向相容到 GPLv3），不能嵌入 GPL-2.0-or-later 的產品。經使用者同意後只作實驗（cargo feature `lindera`）。

## 3. 指標與做法

- **nDCG＠10**（增益 2^g − 1）、**recall＠20**（g ≥ 1 算相關）、**MRR**，依查詢類型分組；另附 P＠10。
- **配對比較**：每個 run 對基線 a 的逐查詢 nDCG＠10 差，算勝／平／負，以及 bootstrap（2000 次、固定種子）的 95% 信賴區間。
- **成本**：索引大小（tantivy 寫到暫存目錄後量檔案大小）、建索引時間、查詢延遲（含斷詞、搜尋、讀 stored field，每題重複 30 次取 p50／p95）。另外把語料重複 50 次（10,000 筆）再量一次。
- 全部在記憶體與暫存目錄進行，沒有連任何 PostgreSQL 資料庫。

- 索引大小：a 約是詞典斷詞（d、e）的 2.5 倍，是純 unigram 的 2 倍。以 10,000 筆不到 2 MB 來看，這個差距在 oxledger 的規模下不重要。

## 5. 失敗案例

每個例子標出查詢、方案、nDCG＠10，以及原因。

### a（M0 現行）

- **「付不了錢」nDCG 0，命中 0 筆。** 查詢端只有 bigram「付不、不了、了錢」，三個在語料裡都沒出現。單字「付」「錢」本來能找到付款失敗的 issue（a2、b、a+uni0.1 都是 0.54）。這是建議第 2 點要修的狀況：一句口語的換句話說，bigram 一個都對不上就會全空。
- **「當機」0.22，命中 1 筆。** 只有 #118「伺服器當機」字面上有「當機」。#119「分頁當掉」、#122「服務掛掉」、#116「閃退」都對不上。a2 靠單字「當」撿回「當掉」（0.46）；加別名後 0.87。
- **「網頁打不開」0，命中 1 筆。** 唯一命中的是 #121「網頁沒有回應」（判為 0），真正相關的 #139「憑證到期網站無法連線」、#118「伺服器當機」都沒有共同的 bigram。別名展開後 0.78。
- **「資料外洩」0.12。** bigram「資料」把 #100、#133、#191 等資料庫與同步的 issue 排到前面；「外洩」只出現在 #31 的長描述裡，真正的權限漏洞 #35、#39、#44 沒被找到。
- **「登不進去」0.22**：只有 #2 字面相同，其他登入失敗的 issue 都用「無法登入」或「登入失敗」。

### a2（查詢端也用單字）

- **「OAuth 錯誤」0（a 是 0.52）。** 單字「錯」「誤」加上 bigram「錯誤」，讓 #56「發票載具號碼驗證錯誤」、#167「Markdown 表格渲染錯誤」等每個有「錯誤」的 issue 拿到三倍的分數，把唯一提到 OAuth 的 #13 擠出前 5 名。
- **「結帳」0.56（a 是 0.97）。** 單字「帳」命中 #63「ATM 虛擬帳號」、#6、#80 等帳號相關的 issue。
- **「API 權限」0.36（a 是 0.76）。** 單字「權」讓所有權限 issue 都拿分，蓋過了「API」，#22、#39 排不到前面。

### b（純 unigram）

- **「卡片」0.19。** 「卡」命中信用卡、卡頓，「片」命中圖片、照片，真正的看板卡片 #106、#157 被擠出前 5 名。這是「登入／載入」這類誤命中的典型樣子；同一題 a 是 0.81。
- **exact 類整體 0.859（a 0.935）**：沒有 bigram 就沒有「字要相鄰」的訊號，「甘特圖」「工時」都受影響。

### c（純 bigram）

- **6 題單字查詢全部 0。** 索引裡只有詞內的 bigram，「信」「慢」「票」「鎖」都找不到東西。其他類別和 a 幾乎一樣。這證明 a 在索引端保留 unigram 是必要的。

### d（ICU4X）

- **「工時」0.44（a 1.00）。** ICU 把「工時報表」斷成「工／時報／表」（「時報」是報紙名），「預估工時」斷成「預估／工／時」，查詢「工時」本身也被斷成「工／時」，變成兩個高頻單字，命中 51 筆。
- **「票」「印」0 筆命中；「慢」0.32。** 「發票」「列印」「很慢」都被當成一個詞，單字查詢只能命中字面上獨立出現的字。
- **「登不進去」斷成「登／不進去」、「閃退」斷成「閃／退」、「載具」斷成「載／具」。** 詞表沒有這些口語與台灣在地用語（libtabe 年代較早），切出的單字又會和「退款」「載入」誤命中。

### e（lindera + CC-CEDICT）

- **「無法登入」0.52（a 0.71）。** e 只有「無法」「登入」兩個詞；「無法」在語料裡很常見，#19「管理員無法以其他使用者身分登入」（判為 0）排到第 2。a 多一個 bigram「法登」，只有字面上連著「無法登入」的 issue 才有，等於一個免費的片語比對。
- **「卡」0.28。** #71「退回原卡」裡獨立的「卡」排第一；真正卡住的 #126「編輯器卡死」（「卡死」是一個詞）、#196「同步卡住」都沒找到。
- **斷法和 ICU 不一致**：「很慢」在 d 是一個詞、在 e 是「很／慢」；「網頁打不開」在 e 是「網頁／打／不／開」。兩個詞典都沒有涵蓋口語的時候，結果取決於詞典剛好收了什麼。

### 別名展開

- **「系統很慢」0.60 → 0.40（變差）。** 「很慢」展開成「延遲、效能、遲緩、逾時、卡頓、slow」，其中「逾時」把 #61「付款頁面逾時」、#11「Session 逾時太短」拉進前 5 名。展開詞也要有範圍（例如只在效能概念下展開），這是 E2 要處理的。
- **「當機」0.22 → 0.87、「網頁打不開」0 → 0.78、「資料外洩」0.12 → 0.57**：提升都來自表裡剛好有對應的規則，見〈限制〉。

## 6. 建議

1. **M1 的索引維持 unigram + bigram（方案 a）**，不引入 ICU4X 或 lindera。理由：品質沒有比較好（d 顯著較差、e 不顯著但偏差），單字查詢會壞，斷詞隨詞典與上下文變動，還多一份資料依賴（e 授權和 GPL-2.0 不相容）。索引大 2.5 倍在 oxledger 的規模下可以接受。
2. **`search.rs` 建議的修改**（由主 session 決定是否採用）：在 `SearchIndex::search` 裡，`tokenize_query` 的詞照舊（boost 3／1），另外把 `tokenize(q)` 裡被 `tokenize_query` 去掉的 CJK 單字也加進 Should 子句，boost 乘上 0.1–0.2（例如標題 0.3、描述 0.1）。這樣「付不了錢」這類 bigram 全空的查詢還有結果，又不會讓「入」「帳」這類單字主導排序。建議同時加兩個測試：「付不了錢」能找到付款失敗的 issue，「登入」的前幾名不會出現只含「載入」的 issue。
   - 權重是在同一份查詢集上挑的（0.1、0.2、0.5 只試了三個值），可能有過擬合。0.1 和 0.2 都顯著改善，0.5 就失去改善，所以建議取 0.1–0.2 之間，不要再調高。
   - 也考慮過「bigram 零命中才退回單字」，但它救不了「當機」這種只命中 1 筆的情況，所以建議一律加低權重單字。
3. **別名展開在 M1 先上一個小版本**，做成資料（ontology 概念的別名），不要寫死在程式裡；展開詞的權重用 1.0 或 0.5 差別不大。上線前要用**不是看過語料的人寫的查詢**（或真實的搜尋紀錄）重做一次 E2，確認提升不是來自別名表剛好貼合這份合成資料。
4. **E8（向量 RRF）照原計畫在別名之後做**。同義詞類在不加別名時只有 0.59，是剩下最大的缺口；E8 的評估應以這一類為主。
5. **看到但這次沒處理的事**（列給主 session 決定）：
   - `tokenize` 把 `_` 當分隔符，`invalid_grant` 會變成 `invalid`、`grant`。對錯誤代碼搜尋目前沒有造成問題，但如果要支援精確搜錯誤碼，可以考慮同時保留整串。
   - 日期、版本號（`v3.2.0` → `v3`、`2`、`0`）也會被拆開，查版本號時精確度會下降，這次的查詢集沒有測到。

## 7. 限制

- **資料是合成的，而且出題、寫語料、標答案是同一個作者。** 偏差包括：
  - 查詢用詞和語料用詞的重疊程度可能比真實情況高（作者知道語料裡寫了什麼），exact 與 decoy 類的分數可能偏樂觀。
  - 同義詞類反過來是刻意設計成字面不重疊，所以那一類的分數可能偏悲觀。
  - **別名表是看過語料後寫的**，別名展開的提升（+0.076）應視為上限。
  - 寫作風格單一：沒有錯字、注音文、簡體字混用、極長的貼 log 的 issue，也沒有真實 Redmine 那種大量模板化的描述。
- **規模小**：200 筆、60 題、378 筆判定。配對 bootstrap 的信賴區間很寬，a2、b、e 和 a 的差異在這個規模下分不出來。
- **判定不完整**：相關度是依主題逐筆標的，沒有用多個方案的結果做 pooling；可能有相關但沒標到的 issue，這對召回較廣的方案（a2、b、加別名）不利。
- **單字查詢只有 6 題**，而且每題的意圖是作者定的（例如「卡」定為卡住，不是信用卡）。
- **放大 50 倍的成本測量是重複同一份語料**，詞彙量沒有變大、重複內容壓縮率高，真實資料的索引會更大。延遲在同一台 Windows 11 機器上量，每次跑有幾 µs 的抖動。
- **lindera 用的是 crates.io 6.2.0 帶的 2020 年版 CC-CEDICT-MeCab**，比現在的 CC-CEDICT 舊；新版可能收了更多口語詞，結果可能不同。ICU4X 中文詞表來自 libtabe，詞頻來自 Google 網頁語料，對台灣當代口語與軟體術語的涵蓋有限。
- 只測了 BM25 的預設參數（k1、b）與 M0 的欄位權重（3／1），欄位權重的消融留給 E2。
