1. 摘要

工具

後端用 insta＋cargo-insta：待審檔、互動審查、CI 不寫入、孤兒偵測、結構化 redaction、glob 語料，並能直接接 nextest。

redaction

不要把 ID 全抹成 [uuid]。依出現順序換成穩定標籤（<user:alice>、<uuid#2>），保留參照關係。

先做

Markdown→HTML、錯誤碼總表、migration 後 schema、AI 請求內容、固定語料搜尋排序。

不做

執行時間、worker 時序、整包 API 回應、視覺截圖（只有 Windows 機器）。

搭配

proptest 驗不變式；cargo-mutants --in-diff 驗斷言有效；每個等待都要硬逾時。

保留

既有 OXLEDGER_UPDATE_API_SPEC 機制保留；只加「CI 有設時忽略」。

5. 哪些適合 golden

對象適合度做法
Markdown→HTML最適合glob! 跑 tests/golden/markdown/*.md；XSS 不變式另寫明確斷言或 proptest
錯誤碼與訊息很適合約 78 個 ErrorCode → status → i18n key 總表一份
OpenAPI spec已有保留現有機制
migration 後 schema適合查 pg_catalog 排序輸出；pg_dump 自 16.10／17.6 起插入隨機 \restrict 鍵（CVE-2025-8714）
HTTP API 回應有條件只拍要守的欄位，先正規化；避免整包回應膨脹
搜尋排序有條件固定語料：名次＋四捨五入分數；frontier／generation 不進快照
AI 執行紀錄有條件送給 provider 的請求（遮 key）與 ai_fake 事件序列；真實模型輸出不拍
時間、worker 時序、截圖不適合維持明確斷言

6. redaction 規則

值規則
World 已知實體 ID<user:alice>、<project:demo>
其他 UUID v7依第一次出現編號 <uuid#1>；同值同標籤
時間<ts>；在意先後就 <ts#n>
xid／frontier／generation<xid> 或不放進快照
浮點數四捨五入 2–4 位
集合語意陣列、map排序；sort_maps(true)
密鑰、token、cookie<secret>＋另一個斷言確認原值不在輸出
路徑、portinsta regex filter

逾時三層（9 小時事件）

1 測試內

每個等待都 tokio::time::timeout，訊息寫出在等什麼。唯一在 cargo test 下也有效的一層。

2 nextest

已有 terminate-after = 10（10 分鐘）；加 global-timeout = "45m"；長迴圈測試個別 override。Windows 上逾時直接 kill。

3 規則

後端測試一律用 nextest；cargo test 只在盯著時除錯單一測試。

11. 已知陷阱

膨脹

只拍要守的欄位；單檔超過約 200 行就拆。

無腦 accept

腳本禁用 always／accept／-u；PR 逐一說明。

redaction 不足

新快照在不同 slot 連跑兩次；Normalizer 集中管理。

redaction 過頭

mutant 存活會指出抹掉太多。

CRLF

insta 讀寫正規化成 LF；其他格式靠 .gitattributes；測 CR 的輸入不放一般文字檔。

密鑰外洩

先遮，再斷言原值不在輸出。
